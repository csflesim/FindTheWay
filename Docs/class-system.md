# 學員管理系統 — 業務邏輯文件

> 目錄導覽見 `Docs/ARCHITECTURE.md`；技術規範（資料表、API、RLS）以根目錄 **AGENTS.md** 為準。
> 本文件描述業務規則：帳號身分、交易流、課堂券生命週期、審核與通知。

---

## 帳號與身分

單一 `profiles` 表（1:1 Supabase auth.users），`role` 四種：

| 角色 | 登入方式 | 權限 |
|------|---------|------|
| member 會員 | LINE 登入（`/m/login`） | 前台：報名、購券、管理名下學員 |
| teacher 教師 | Email 密碼或 LINE（`/m/teacher/login`） | 教師專區：課表、點名、請假 |
| staff 管理員 | 帳號密碼（`/sys-admin/login`） | 後台全功能 |
| admin 超級管理員 | 同上 | 後台全功能＋系統管理 |

- 權限由資料庫 RLS 強制（`is_staff()`），非僅前端判斷
- 教師身分解析：`/api/teacher/me` 以 Email / LINE userId 比對教師檔並自動綁定、升級角色
- 後台可在「教師管理」直接為教師設定登入密碼（自動開通帳號）；「人員管理」管理 staff/admin/teacher 帳號

### 一帳號多學生（trip.com 旅客模式）

- 會員名下可掛多位學員（`students`，關係：子女/配偶/其他）；「本人」為虛擬學員
- 前台新增學員 → `status 待審核` → 後台學員管理核准/拒絕 → 核准後出現在名下列表
- 後台可直接建立學員（免審核），並支援「外部學員」（無會員帳號，掛單位/班級，供校外合作點名）

## 課程模型

- `courses` 扁平模型：內部/外部可複選；班表為文字（`每週六 10:00–12:00` 或單日 `YYYY/MM/DD hh:mm–hh:mm`）
- 教師課表、教室課表、Dashboard「即將開課」皆由班表文字即時展開（`src/lib/schedule.ts`），無獨立場次表
- 教師日曆的可排課時段（幾點到幾點）由後台「參數管理 → 上課時間」設定
- `enrolled`（已報名人數）＝該課程已付款訂單數，**自動計算**，後台不可手改

## 交易流（訂單 → 課堂券）

```text
前台下單（單堂直購 / 課堂券扣抵 / 買券包）
  └▶ orders「待確認」＋ 觸發工作流「報名建立」
後台訂單管理「確認付款」（/api/orders/confirm）
  ├▶ 券包：依 products.validity_months 發 tickets（TK-訂單號-XX，含效期）
  ├▶ 課堂券扣抵：自動核銷來源券包 1 張（無券可扣 → 擋下並提示）
  ├▶ 課程訂單：同步 enrolled
  └▶ 觸發工作流「付款成功」「報名確認」（LINE 推播＋Email，套訊息管理模板）
```

### 課堂券生命週期

| 狀態 | 進入方式 |
|------|---------|
| 未使用 | 確認付款發券 |
| 已使用 | ① 課堂券扣抵訂單確認付款時自動核銷 ② 點名「出席」自動核銷（記錄票券 id，改缺席/移除自動退回） |
| 已失效 | 售後收回 |

- 轉讓：會員把未使用券轉給名下已核准學員（`/api/member/transfer-tickets` 伺服器端驗證），票券 `transferred_to` 記受讓人
- 未指定學員的票券屬「本人」；核銷時依學生姓名解析其名下（含受讓）票券，效期近的先扣
- 券餘額 = 未使用票券數，前台「訂單 & 課堂券」與後台卡券管理即時一致

### 售後

已付款且有已消耗票券的訂單可發起售後：選擇收回的未使用票券（設「已失效」）、退款金額（建議值＝原價 × 未使用/總堂數）→ 訂單標「已售後」，不可撤銷；售後管理頁為唯讀歷史。

## 點名與出席

- 教師端：近 7 天場次點名，名單自動由該課程已付款報名訂單帶入，可手動加減人
- 後台端：課堂管理（外部課程點名抽屜）與出席管理（roster 總覽/篩選/統計）
- 兩端共用 `/api/attendance/save`：出席自動核銷、退選自動退券、重複儲存冪等
- 紀錄存 `course_attendance`（一課一日一筆，records jsonb 含票券核銷對照）

## 訊息與通知

- **模板**：訊息管理設計器（LINE Flex / Email 區塊），存 `message_templates`，跨裝置共用
- **工作流**：`workflows` 表；事件觸發（付款成功、報名建立/確認/取消）由 `src/lib/workflow-engine.ts` 執行——比對啟用中工作流的觸發節點，沿連線發送（含條件分支），變數帶入真實訂單資料，寄給該訂單會員
- **直接發送**：LINE 指定/全體推播、Email 指定/全體發信（撈所有有真實信箱的會員逐一寄）
- 所有發送記入 `message_logs`（發送歷史頁）
- **待辦**：課前 N 小時提醒等排程類通知，待與 Cron 功能整併（參數頁「通知設定」暫停用）

## 上線注意

- 正式環境設定存 `settings` 表；敏感值 AES-256-GCM 加密（金鑰 `SETTINGS_ENCRYPTION_KEY`）
- LINE：Login/Messaging 分兩個 Channel（需同 Provider，userId 才一致）；callback 與 webhook URL 要登記正式網域
- `supabase/schema.sql` 為毀滅性重建腳本，日常改欄位一律用 ALTER
